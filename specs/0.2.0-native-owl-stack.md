# OAEI-Bio-ML-eval 0.2.0 — native shared-OWL migration

**Target:** `0.2.0`, Python `>=3.10`. **Current baseline:** `0.1.0.dev0`, Python `>=3.12`.
**Status:** repository-owned O0–O5 candidate implementation complete; public release remains
blocked by the unchecked external/hosted gates in §14.

**Audit commit:** `900ba7f242f254d08b0e01e6826975c61d0438b2` (2026-07-16). Re-locate
implementation references by symbol if paths or lines drift.

## 1. Outcome

Official Bio-ML coherence must load each ontology once into the shared Java-free core, add the
alignment bridge as immutable shared-model axioms, and classify the resulting read-only view
with native pyHermiT or pyELK. No released code starts a JVM, invokes ROBOT, imports DeepOnto,
parses OWLAPI logs, or exports and reparses a merged ontology.

Typed and equivalence metrics never needed an OWL reasoner. They remain a separate, lightweight
surface whose numeric and file-format behavior is frozen by existing tests and new baseline
artifacts. "Remove Java" is not authorization to rewrite those metrics.

## 2. Current audit and removal scope

The current coherence path contains:

- `RobotReasoner`, subprocess/process-group control, ROBOT/JAR discovery, heap variables,
  functional-syntax bridge files, SPARQL signature queries, and log-derived unsatisfiable sets;
- `DeepOntoReasoner`, JPype/OWLAPI object handling, JVM heap setup, and its optional dependency;
- CLI/backend arguments for `robot`, `deeponto`, `owlapi`, JAR/Java commands, and heap;
- environment variables such as `ROBOT_JAR`, `ROBOT_JAVA_ARGS`, and
  `OAEI_COHERENCE_BACKEND=robot`; and
- skip-guarded integration tests that require ROBOT or DeepOnto.

All are deleted or replaced for `0.2.0`. ROBOT 1.9.10 remains only in quarantined baseline
provenance and an opt-in development oracle. It is not a runtime, optional, test-suite, wheel,
sdist, container, or official deployment requirement.

References to "DeepOnto TSV" as a simple accepted column layout are renamed to neutral
"alignment TSV" terminology without changing parsing. File compatibility does not imply a
DeepOnto dependency.

## 3. Shared input contracts

Snapshot-first functions accept `pyowl_core.OntologyView`, the read-only protocol implemented by
the sibling concrete `OntologySnapshot`, `OntologyOverlay`, and `OntologyComposite`:

```python
def score_global_coherence(
    correspondences,
    source: pyowl_core.OntologyView,
    target: pyowl_core.OntologyView,
    *,
    reasoner: Literal["hermit", "elk"] = "hermit",
    timeout_s: float | None = 7200.0,
) -> CoherenceReport: ...

def score_reference_coherence(
    correspondences,
    source: pyowl_core.OntologyView,
    target: pyowl_core.OntologyView,
    *,
    reasoner: Literal["hermit", "elk"] = "elk",
    timeout_s: float | None = 7200.0,
) -> CoherenceReport: ...

def score_local_coherence(
    committed_top1,
    source: pyowl_core.OntologyView,
    target: pyowl_core.OntologyView,
    *,
    reasoner: Literal["hermit", "elk"] = "hermit",
    timeout_s: float | None = 7200.0,
) -> CoherenceReport: ...
```

Passing a snapshot/overlay/composite retains exact object identity and shared lazy indexes. An
Exact-OM `OwlOntologySource` may be passed through `pyowl_core.coerce_snapshot`; its
`owl_snapshot()` method is called once. No path or source bytes are requested after handoff.

Existing `score_*_coherence_files(...)` functions stay as convenience wrappers. Each calls
`coerce_snapshot` exactly once for source and once for target, then delegates to the snapshot
function. They accept the complete core `OntologyInput` surface and delegate format, text/binary
stream, import, resolver, and source-ownership rules to the core instead of narrowing them.
Network imports remain opt-in through an explicit resolver.

Cross-process timeout workers use only `encode_snapshot`, `decode_snapshot`, or verified
`open_snapshot(..., mmap=True)`. They never pickle core objects and never send original OWL paths
for a worker to reparse.

## 4. Composite view and bridge

Coherence uses the core's frozen zero-copy composition API:

```python
bridge_delta = pyowl_core.OntologyDelta(add_axioms=frozenset(bridge_axioms))
merged = pyowl_core.compose_views(
    source,
    target,
    delta=bridge_delta,
    roles=("source", "target"),
)
assert isinstance(merged, pyowl_core.OntologyComposite)
```

`OntologyComposite` is a sibling `OntologyView`, not a snapshot or overlay subclass.
`compose_views(*views, delta=None, roles=None)` retains every base arena, merges iterators and
shared lazy core indexes, preserves document-scoped anonymous identities, and adds the bridge
delta without copying either ontology. Its deterministic composition manifest, roles,
structural/logical/signature fingerprints, and base provenance reach both reasoners.
`coerce_snapshot(merged) is merged` is mandatory; neither reasoner may materialize it
in-process. The one permitted materialization is the core wire encoding used to feed a
terminable worker process (§§3, 5); provenance records whether in-process identity or
verified wire was used.

OAEI must not invent a second OWL model, implement a private union view, or silently flatten two
snapshots. A compatible released core containing `OntologyComposite`/`compose_views` is a 0.2.0
release prerequisite. The one composite is reused for the merged signature and either reasoner
pass.

Bridge behavior is frozen:

- a 2-tuple defaults to `=`;
- `=`/`equivalent`/`equiv` produce `EquivalentClasses(source, target)`;
- `<` aliases `<=` and produces `SubClassOf(source, target)`;
- `>` aliases `>=` and produces `SubClassOf(target, source)`;
- duplicate normalized triples are removed and the axiom set is canonical;
- self-pairs are dropped;
- unsupported relations fail in submission APIs, while existing repaired-reference loaders drop
  `?` and unrecognized flagged rows as they do now; and
- malformed IRI validation and `skip_invalid` behavior remain explicit and tested.

No bridge `.ofn`, merged `.owl`, temporary RDF graph, or parser pass is created.

## 5. Native reasoner policy

The coherence layer has two adapters, both consuming the exact merged `OntologyView`:

- `HermiTReasoner` delegates to pyHermiT for the DL classification and is the default for global
  submissions and local rank-1 coherence;
- `ELKReasoner` delegates to pyELK for OWL 2 EL classification and is the default for repaired
  reference coherence at SNOMED scale.

The adapters use public reasoner constructors that call `coerce_snapshot`; they do not translate
to OAEI records. Reasoner-private compiled IR may be cached by logical fingerprint and backend
version, but cannot change or leak through the shared model.

The existing policy remains: if a preferred HermiT classification exceeds its enforceable
wall-clock timeout, classify the exact same composite view with pyELK and report
`lower_bound=True` and
`reasoner_used="elk"`. Any worker boundary uses core wire, so fallback performs no OWL parsing.
ELK profile limitations and ignored/unsupported constructs are included in provenance; a lower
bound must never be presented as an exact DL result.

Timeout enforcement is reasoner-specific. pyHermiT enforces `timeout_s` cooperatively
through its `ReasonerConfig.timeout`/`interrupt()` contract and may run in-process. pyELK
deliberately exposes no cooperative timeout or interrupt API (a pyELK non-goal), so every
ELK classification bounded by `timeout_s` — including the fallback pass — runs in a
terminable worker process fed by core wire; exceeding the bound terminates the worker and
is reported as a timeout, never coerced into a coherence value.

Other HermiT failures, unsupported inputs, corrupt snapshots, resource exhaustion, and worker
crashes are errors, not automatic ELK fallbacks. An explicit `reasoner="elk"` result is also
marked as the EL result/lower-bound methodology according to the existing scoring contract.

## 6. Coherence metric semantics to preserve

### Global and repaired reference

The denominator is the sorted set of named classes in the single merged view, excluding
`owl:Thing`, `owl:Nothing`, and anonymous expressions. The numerator is the sorted unsatisfiable
named-class set, excluding `owl:Nothing`. The numerator must be a subset of the denominator.

`global_coherence` retains its current historical key and means **degree of incoherence**:

```text
unsatisfiable_count / union_class_count
```

Zero means clean; higher is worse; an empty denominator yields `0.0`; results are rounded to 12
decimal places. Documentation must say this at every public entry point. Renaming or reversing it
is a future metric-version decision, not part of Java removal.

If the merged view is **inconsistent** (not merely incoherent), classical semantics makes
every named class unsatisfiable: the unsatisfiable set equals the full denominator and
`global_coherence` is `1.0`. Adapters therefore establish consistency before requesting
unsatisfiable classes. The HermiT adapter must convert pyHermiT's default
`InconsistentOntologyError` into this result rather than letting it escape; pyELK's quiet
collapsed taxonomy (every committed named class in the bottom node) yields the same set,
so both backends agree. The report records `inconsistent: true` in provenance, and an ELK
result additionally keeps its lower-bound/EL labeling (an EL-consistent view may still be
DL-inconsistent).

Repaired-reference reports retain `asserted_correspondences` after normalization/filtering.

### Local

For each query with a non-empty ranked pool, the current rank-1 target is committed. The bridge
deduplicates repeated pairs, but query occurrences are retained for aggregation. One batched
classification is performed. A query is incoherent when its source or committed target is
unsatisfiable. Queries without a commitment are excluded. `local_coherence` is the 12-decimal
mean and `local_coherence_queries` is the count. The inconsistent-view rule above applies
unchanged: an inconsistent merged view makes every committed query incoherent, so
`local_coherence` is `1.0` with `inconsistent: true` recorded in provenance.

The open methodological question about batched blame versus per-query classification is not
silently resolved in this migration. A future change needs a new metric-methodology version and
new official baselines.

### Task aggregation

Every metric family exposes `aggregate_across_tasks(..., average="macro" | "micro")`.
`"macro"` gives every task equal weight and is the Bio-ML default. `"micro"` pools sufficient
statistics and is the Conference default: global precision/recall/F1 are recomputed from summed
TP/predicted/reference counts, ranking and local-coherence means are weighted by their exact
contributing-query counts, and global incoherence is recomputed from summed unsatisfiable/signature
counts. It is forbidden to call a weighted mean of task percentages "micro" when exact
denominators are available.

Counts sum in both modes. Per-task `reasoner_used` and `lower_bound` do not aggregate. A statistic
that is not compositionally recoverable from per-task summaries, such as the median of pooled
ranks, is omitted from the micro summary unless the caller supplies raw sufficient statistics;
it is never approximated by a mean of medians. Existing per-task key names and JSON numeric types
remain unchanged apart from additive aggregation counts and the versioned provenance block.

## 7. Typed and equivalence metric freeze

The following modules are not reasoner migration targets: `typed/`, `equivalence/`, generic TSV
I/O, and `hierarchy.py` used by typed metrics. Their existing golden inputs/outputs become
committed `metric-contract/1` baselines before coherence edits.

Required preservation includes:

- global P/R/F1 set behavior, coherence-aware arithmetic, local MRR/Hits@k, candidate ordering,
  tie behavior, and 12-decimal quantization;
- typed preferred-relation selection, relevance gains, hierarchy-aware nDCG, filtering,
  selectable exact micro/macro aggregation, and diagnostic keys;
- TSV column names, OAEI Alignment RDF interpretation, block/ranked formats, empty-input behavior,
  and error classes/messages relied on by CLIs; and
- base-install dependency freedom for metric cores. RDFLib remains confined to the `rdf` extra.

Python 3.10 compatibility fixes in these modules must be mechanical and baseline-identical.
They do not acquire `pyowl-core`, pyHermiT, pyELK, projector, Exact, or native imports.

## 8. Public API and CLI migration

`CoherenceReasoner` is narrowed to shared views and native classification; backend-private
`MergedOntology` handles and `dispose` disappear when no longer needed. `UnsatResult` gains
versioned provenance while preserving sorted unsatisfiable IRIs, `reasoner_used`, and elapsed
seconds.

The coherence CLI keeps `--reasoner hermit|elk`, `--timeout`, output, and invalid-IRI policy.
It removes:

- `--backend robot|deeponto|owlapi`;
- `--robot-jar`, Java executable/command, and JVM heap flags; and
- ROBOT/DeepOnto environment variables and discovery messages.

Because the current package is a development release, removed backend flags fail with a concise
0.2 migration message rather than remaining executable Java shims. Examples and help contain no
Java installation step. The structural proxy remains distinctly labeled non-official.

## 9. Packaging and Python 3.10

The implementation release performs, together:

- set project and module version to `0.2.0` and `requires-python = ">=3.10"`;
- keep base dependencies empty;
- keep `rdf = ["rdflib>=7.0"]` only if its resolved versions support the full Python matrix;
- replace `reasoner` with compatible pins/ranges for `pyowl-core`, pyHermiT, and pyELK;
- delete the `deeponto` extra and every external ROBOT prerequisite; and
- publish wheels/sdist that install and run with no Java or Rust toolchain required by this
  package itself. Native dependency wheels must cover claimed platforms; unsupported platforms
  receive an actionable optional-extra error, not an accidental Java fallback.

Audit Python 3.10 syntax, annotations, stdlib APIs, Hatch metadata, dependency resolution, type
checking, and all CLIs. CI covers 3.10, 3.11, 3.12, 3.13, and newer supported versions. The 0.2
version/metadata change lands only with implementation, never as a specs-only claim.

## 10. Provenance and reproducibility

Every official report contains or links to a `coherence-provenance/1` object with:

- OAEI package and metric-methodology version;
- Python/platform and scoring command/API options;
- core package/API, model schema, wire version, composite fingerprints/role manifest, and
  source/target structural/logical/signature fingerprints;
- document fingerprints, closure/import-resolution manifests, loader diagnostics, and whether
  in-process identity or verified wire was used;
- normalized bridge count/fingerprint and dropped/self/invalid correspondence counts;
- requested/actual reasoner, package/backend/build versions, supported profile diagnostics,
  timeout, elapsed time, fallback reason, and lower-bound status; and
- denominator/numerator digests and counts.

Leaderboard jobs pin the full environment and store the provenance next to results. Two numbers
with different reasoner/methodology versions are never silently combined. Paths, credentials,
temporary files, Python object IDs, and nondeterministic timestamps are excluded from semantic
digests.

## 11. Baselines and differential verification

Before deleting Java code, capture ROBOT 1.9.10 outputs on the current three-class clash fixture,
clean/equivalent/subsumption fixtures, import cases, HermiT timeout gate, malformed alignments,
and legally available representative Bio-ML tasks. Record ontology/alignment hashes,
unsatisfiable IRI sets, denominator sets, metrics, commands, JDK/ROBOT/reasoner versions, and
logs. DeepOnto captures remain exploratory labels and are not mixed with ROBOT results.

The baseline harness becomes a quarantined manual oracle excluded from releases. Ordinary CI has
no Java. Native pyHermiT must match the pinned HermiT expected unsatisfiable set/count on supported
DL fixtures; pyELK must match the pinned ELK expected set/count on EL fixtures. Version-driven
differences on real ontologies require ontology experts to classify them and either pin a
compatible backend or approve a new metric-methodology version—never merely update expected
leaderboard numbers.

Tests also prove:

- exact snapshot identities reach composition and reasoner adapters in-process;
- path/stream wrappers call core coercion once per ontology;
- composite/overlay creation makes no ontology-sized copy and leaves bases unchanged;
- bridge normalization matches current aliases, sorting, dedupe, self-drop, and reference-drop
  rules;
- HermiT timeout uses the same composite view for ELK, while other errors do not fallback;
- an inconsistent merged fixture yields `global_coherence == 1.0` and `inconsistent: true`
  from both reasoner adapters, and `InconsistentOntologyError` never escapes the HermiT
  adapter;
- numerator is a denominator subset and Thing/Nothing exclusions are symmetric;
- file and snapshot APIs return the same metric JSON/digests;
- core wire workers parse zero OWL documents;
- typed/equivalence baseline bytes and numeric dictionaries remain unchanged; and
- unequal-task-size fixtures prove Conference micro and Bio-ML macro yield their independently
  computed expected values; and
- imports/dependencies/source scans contain no runtime Java, ROBOT, DeepOnto, JPype, OWLAPI, or
  projector/Exact coupling.

## 12. Performance and scale

Benchmarks separate source/target load, zero-copy composition, bridge overlay, reasoner compile,
classification, fallback, and reporting. They record wall/CPU time, peak and incremental RSS,
worker-wire bytes, core-cache hits, axiom/class counts, and fingerprints.

The merged view must not materialize source/target structures twice. Bridge memory is `O(M)` for
`M` normalized correspondences. Signature calculation and result reporting are streaming or
indexed; they do not serialize the ontology. GO/NCIT and a licensed SNOMED-scale task are release
evidence. Relative baselines on a pinned runner fail above 20% RSS or 25% wall-time regression
unless an owner, cause, accepted delta, and expiry release are recorded. Correctness and
no-duplicate-parse gates cannot be waived.
