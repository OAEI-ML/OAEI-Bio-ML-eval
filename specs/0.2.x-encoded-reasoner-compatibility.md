# OAEI-Bio-ML-eval 0.2.x — encoded reasoner compatibility

**Target:** include before the unpublished `0.2.0` release if possible; otherwise `0.2.1`.
**Status:** specified, not implemented. This is a compatibility/performance update, not a metric
methodology change.

**Depends on:** the implemented `0.2.0-native-owl-stack.md` contracts, pyowl-core WP17, pyELK
WP14, and pyHermiT WP18.

## 1. Scope

OAEI continues to build one `OntologyComposite` from the exact source/target views plus bridge and
passes that composite to a public reasoner. The reasoner—not OAEI—requests and decodes
`EncodedStructuralView` and owns its compiled IR.

OAEI MUST NOT:

- import or inspect `EncodedStructuralView` buffers, `pyowl_core._native`, or reasoner internals;
- flatten the composite, serialize private IR, materialize scalar axioms to help a reasoner, or
  hand it original OWL paths;
- cache schema-local dense IDs; or
- make native acceleration a dependency of typed/equivalence metrics or the base installation.

Global/reference/local coherence formulas, denominators, inconsistent-ontology policy, HermiT
timeout-to-ELK fallback, lower-bound labels, aggregation, rounding, CLI, and result keys remain
exactly those of the 0.2 metric contract.

## 2. In-process and worker handoff

In-process adapters pass the exact composite identity once. An encoded-capable reasoner may retain
its public core owner for the native session lifetime; OAEI only manages the documented reasoner
lifecycle.

Timeout workers continue to receive a verified core wire/mmap snapshot, never source paths or
pickled objects. Opening the mapped snapshot may expose encoded columns without parsing OWL or
copying source/target bases. The same mapped composite is used by a HermiT timeout fallback to ELK
where process policy permits; otherwise the existing verified core artifact is reopened, not the
ontology source reparsed.

Scalar-only compatible core/reasoner installations remain functional. `reasoner` extras may use
native wheels when present but retain their complete pure/scalar fallback. A malformed advertised
encoded capability fails as a protocol error and does not trigger path-based retry.

## 3. Dependencies and packaging

Update `reasoner` dependency ranges only after the exact core, pyELK, and pyHermiT releases/wheels
pass the OAEI matrix. Capability negotiation uses public version/schema metadata rather than
lexical package-version assumptions.

The base, `rdf`, and reasoner-extra dependency separation remains unchanged. Projector, Exact-OM,
Horned-OWL, OWLAPI, ROBOT, DeepOnto, JPype, Java, and Rust crates do not become OAEI runtime
dependencies. Python 3.10 and every currently claimed interpreter remain supported.

If `0.2.0` is still unreleased, compatible bounds and tests may land in that candidate without
changing metric or package version. If `0.2.0` has shipped, the dependency/provenance/docs update
is a `0.2.1` patch. A specs-only change never bumps runtime metadata.

## 4. Provenance

Extend `coherence-provenance/1` additively with a `compiler_handoff` block containing only public
diagnostics:

- core encoded schema/descriptor and direct/decoded/mmap/composite owner kind;
- requested/selected reasoner backend and scalar/encoded compilation path;
- reasoner compiler/native schema and implementation version; and
- parser, scalar materialization, core-wire, copied-byte, per-row FFI, and base-flattening counter
  deltas when the installed versions expose them.

These fields do not enter metric numerators/denominators or the metric-methodology version. Missing
optional counters are recorded as unavailable, never fabricated as zero. Semantic result digests
exclude nondeterministic timing, addresses, object IDs, paths, and machine-local buffer facts.

The adapter recognizes an optional, pre-release `backend.compiler_handoff` compatibility
attestation. The field remains unadvertised until the reasoner releases freeze their public
diagnostics. Its absence is a scalar-compatible no-op. If present, it is an exact mapping with
`schema_name`, `schema_version`, `model_schema`, `descriptor_sha256`, and `buffer_widths`; the
descriptor digest and all 11 named item widths must match frozen structural-columns schema v1.
Malformed or partial advertising fails closed. This attestation alone does not select a path or
prove that the current session used encoded-native compilation.

## 5. Verification

The existing 0.2 suite runs unchanged against scalar and encoded reasoner compilation. Add focused
tests proving:

- source, target, bridge composite, reasoner adapter, and in-process native session retain the
  expected identity/owner chain;
- encoded-native reasoners cause zero parser, resolver, scalar axiom/term, core-wire, per-row FFI,
  or base-flattening counter delta in-process;
- worker/mmap execution parses zero OWL documents and yields identical denominator/numerator sets,
  inconsistency flags, fallback policy, metrics, JSON, and digests;
- pyHermiT's multi-level-superclass incoherence regression and OAEI's already-incoherent fixture
  pass forced native and verify modes;
- ELK unsupported-feature/lower-bound reporting is unchanged;
- capability absence, incompatible schema, corrupt buffer, timeout, cancellation, worker crash,
  and pure-wheel paths preserve typed public errors; and
- base/`rdf` installations do not import core or reasoners, while the reasoner extra remains
  Java-free on Python 3.10 through the current matrix.

No golden metric number is updated merely because a compilation path differs.

## 6. Performance evidence

Rerun the existing phase benchmark on the same pinned Conference/Bio-ML, GO/NCIT, and licensed
SNOMED-scale inputs where available. Record source/target load, composition/bridge, encoded-view
publication, reasoner compile/session, classification, fallback, reporting, CPU/wall time, RSS,
copy/materialization/FFI/wire counters, and exact result hashes.

The existing maximum 25% wall-time and 20% RSS regression gates remain. In addition, the selected
encoded-native reasoner must satisfy its own release thresholds and in-process OAEI must introduce
no ontology-sized representation beyond the consumer's necessary private reasoning IR. Results
from tiny fixtures or different semantic workloads are diagnostic only.

## 7. Owned implementation surface and completion

Expected changes are limited to coherence reasoner adapters/provenance, timeout-worker handoff,
dependency ranges, compatibility tests, benchmark evidence, docs/changelog/SBOM, and possibly the
patch version decision. Typed/equivalence implementation is out of scope.

Completion requires exact metric/result parity, pure/scalar/native and Python-version matrices,
identity/no-materialization/copy evidence, accepted scale benchmarks, audited artifacts, and a
published compatibility matrix naming exact core/pyELK/pyHermiT/OAEI revisions. Remaining official
deployment and leaderboard gates in the 0.2.0 spec are not waived.
